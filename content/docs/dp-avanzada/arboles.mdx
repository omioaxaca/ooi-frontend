## Antes de empezar

Necesitas árboles enraizados y postorden. La ventaja de un árbol es que, una vez fijada la decisión sobre un vértice, sus subárboles hijos pueden quedar independientes. El estado debe expresar toda la información que el padre necesita conocer.

## Problema: elegir vértices sin vecinos elegidos

Cada vértice tiene un peso, que puede ser negativo. Buscamos un conjunto de peso máximo sin elegir simultáneamente los extremos de una arista. Se permite elegir el conjunto vacío.

Para cada vértice guardamos:

1. `tomar[vertice]`: mejor suma en su subárbol si lo elegimos.
2. `omitir[vertice]`: mejor suma si no lo elegimos.

Si tomamos el vértice, ningún hijo puede tomarse. Si lo omitimos, cada hijo puede escoger su mejor opción:

$$tomar[v]=peso[v]+\sum_{hijo}omitir[hijo],$$
$$omitir[v]=\sum_{hijo}\max(tomar[hijo],omitir[hijo]).$$

## Por qué basta ese estado

En un árbol, no hay aristas entre subárboles hijos distintos; una arista así crearía un ciclo. Por eso sus decisiones no interfieren después de saber si el padre está elegido. En un grafo general esta independencia puede desaparecer.

Una hoja tiene `tomar = peso` y `omitir = 0`. Calculamos hijos antes que padres. La respuesta final es el mayor de los dos estados de la raíz.

## C++17: postorden iterativo

Construimos primero un orden con padres antes que hijos y luego lo procesamos al revés. Así evitamos recursión de profundidad lineal.

```cpp test
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int cantidad;
    cin >> cantidad;
    vector<long long> peso(cantidad);
    for (long long& valor : peso) cin >> valor;
    vector<vector<int>> vecinos(cantidad);
    for (int indice = 1; indice < cantidad; indice++) {
        int origen, destino;
        cin >> origen >> destino;
        vecinos[origen].push_back(destino);
        vecinos[destino].push_back(origen);
    }
    vector<int> padre(cantidad, -1), orden = {0};
    for (int indice = 0; indice < cantidad; indice++) {
        int actual = orden[indice];
        for (int vecino : vecinos[actual]) {
            if (vecino == padre[actual]) continue;
            padre[vecino] = actual;
            orden.push_back(vecino);
        }
    }
    vector<long long> tomar = peso, omitir(cantidad, 0);
    for (int indice = cantidad - 1; indice > 0; indice--) {
        int actual = orden[indice], superior = padre[actual];
        tomar[superior] += omitir[actual];
        omitir[superior] += max(tomar[actual], omitir[actual]);
    }
    cout << max(tomar[0], omitir[0]) << '\n';
}
```

Entrada:

```text input
5
3 2 4 5 1
0 1
0 2
1 3
1 4
```

Salida:

```text output
10
```

Podemos elegir vértices 2, 3 y 4, de pesos 4, 5 y 1. Si elegimos la raíz 0, ya no podemos elegir 2 y el mejor valor es 9. Elegir siempre el vértice de mayor peso disponible no reemplaza la comparación entre estados.

## Coste y extensiones

Cada arista aporta una transición: tiempo y memoria $O(n)$. El código exige un árbol no vacío y sumas representables en `long long`. Si todos los pesos son negativos, la respuesta es cero porque el conjunto vacío está permitido.

Para recuperar los vértices elegidos, empieza con la decisión óptima de la raíz. Si el padre fue elegido, obliga a omitir al hijo; si no, compara sus estados. Para responder una DP para **todas las raíces**, una técnica posterior es rerooting: calcula contribuciones hacia abajo y hacia arriba sin rehacer el árbol completo por raíz.
