## ¿Qué es un MST?

**Antes de empezar:** necesitas un grafo no dirigido ponderado y DSU. Un MST minimiza el peso de la red completa, no la distancia desde una fuente a cada destino. Puede contener pesos negativos y no tiene por qué ser único si hay empates.

Si el grafo no es conexo, no existe un árbol que abarque todos los vértices. Kruskal todavía encuentra un bosque de expansión mínima por componentes, pero debes distinguir esa salida de un MST completo.

**Analogía:** Necesitas conectar varias ciudades con carreteras gastando lo menos posible. No necesitas todas las carreteras posibles — solo las suficientes para que todas las ciudades estén conectadas. El **Árbol de Expansión Mínima** (Minimum Spanning Tree) es exactamente eso: un subconjunto de aristas que conecta todos los nodos con el **menor peso total**.

**Propiedades:**

- Tiene exactamente $n - 1$ aristas (es un árbol).
- Conecta todos los $n$ nodos.
- El peso total es el mínimo posible.

## Kruskal: ordenar y unir

1. Ordena todas las aristas por peso (de menor a mayor).
2. Para cada arista, si conecta dos componentes diferentes, agrégala.
3. Usa **Union-Find** para verificar componentes.

La propiedad del corte justifica la elección: una arista de peso mínimo que cruza entre una componente actual y el resto puede pertenecer a algún MST compatible con las elecciones anteriores. Si otra solución usa una arista más cara para cruzar ese corte, podemos intercambiarlas sin perder conectividad ni aumentar el peso.

```cpp test
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

struct Arista {
    int u, v, w;
    bool operator<(const Arista &o) const { return w < o.w; }
};

int padre[100005], rk[100005];

int encontrar(int x) {
    if (padre[x] != x) padre[x] = encontrar(padre[x]);
    return padre[x];
}

bool unir(int a, int b) {
    a = encontrar(a); b = encontrar(b);
    if (a == b) return false;
    if (rk[a] < rk[b]) swap(a, b);
    padre[b] = a;
    if (rk[a] == rk[b]) rk[a]++;
    return true;
}

int main() {
    int n, m;
    cin >> n >> m;

    vector<Arista> aristas(m);
    for (auto &[u, v, w] : aristas) cin >> u >> v >> w;

    sort(aristas.begin(), aristas.end());

    for (int i = 1; i <= n; i++) { padre[i] = i; rk[i] = 0; }

    long long costoTotal = 0;
    int aristasUsadas = 0;

    for (auto &[u, v, w] : aristas) {
        if (unir(u, v)) {
            costoTotal += w;
            aristasUsadas++;
            if (aristasUsadas == n - 1) break;
        }
    }

    if (aristasUsadas == n - 1) {
        cout << "Costo MST: " << costoTotal << endl;
    } else {
        cout << "No es posible conectar todos los nodos" << endl;
    }

    return 0;
}
```

Entrada:

```text input
4 5
1 2 1
2 3 2
3 4 3
1 4 10
1 3 4
```

Salida:

```text output
Costo MST: 6
```

Las aristas de pesos 1, 2 y 3 conectan los cuatro vértices. La inicialización cuesta $O(V)$ y ordenar cuesta $O(E\log(E+1))$; las uniones agregan un coste amortizado casi lineal. La suma usa `long long`, aunque cada peso individual quepa en `int`.

## Prim: expandir desde un nodo

Similar a Dijkstra: empieza desde un nodo y siempre agrega la arista más barata que conecte un nodo nuevo.

Prim prioriza el **peso de una arista de conexión**, no la distancia acumulada desde la raíz. Esa diferencia de clave es fundamental. El fragmento de abajo usa -1 para indicar desconexión; si admites pesos negativos y el coste válido puede ser -1, devuelve una marca de éxito separada en vez de depender de ese centinela.

```cpp
#include <queue>

typedef pair<int,int> pii;
vector<pii> adj[100005];
bool enMST[100005];

long long prim(int n) {
    priority_queue<pii, vector<pii>, greater<pii>> pq;
    pq.push({0, 1});
    long long costo = 0;
    int nodos = 0;

    while (!pq.empty() && nodos < n) {
        auto [w, u] = pq.top(); pq.pop();
        if (enMST[u]) continue;

        enMST[u] = true;
        costo += w;
        nodos++;

        for (auto [v, peso] : adj[u]) {
            if (!enMST[v]) {
                pq.push({peso, v});
            }
        }
    }

    return (nodos == n) ? costo : -1;
}
```

**Complejidad:** $O((V + E) \log V)$

## ¿Kruskal o Prim?

| Criterio                       | Kruskal                   | Prim                                                                        |
| ------------------------------ | ------------------------- | --------------------------------------------------------------------------- |
| Grafo disperso ($E \approx V$) | ✅                        | ✅                                                                          |
| Grafo denso ($E \approx V^2$)  | Ordenar puede ser costoso | La variante con matriz cuesta $O(V^2)$; no es la variante con heap mostrada |
| Implementación                 | Más simple                | Más compleja                                                                |
| Necesita Union-Find            | Sí                        | No                                                                          |
