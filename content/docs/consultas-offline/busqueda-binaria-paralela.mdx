## Antes de empezar

Necesitas búsqueda binaria y una condición monótona: una vez verdadera, debe seguir siendo verdadera al añadir eventos. Aquí «paralela» significa procesar varias búsquedas conjuntamente, no usar hilos de ejecución.

Esta técnica es offline: conoce todas las consultas para agruparlas. No implica que el problema sea de solo salida.

## Qué trabajo queremos compartir

Hay eventos numerados de 1 a $n$. Cada consulta pregunta por el primer evento tras el cual se cumple su condición. Si evaluar un punto medio requiere reconstruir una estructura aplicando todos los eventos anteriores, hacerlo por separado para cada consulta repite mucho trabajo.

En una ronda, cada consulta elige su punto medio. Las agrupamos en cubetas por ese número, reiniciamos la estructura y recorremos los eventos una sola vez. Al llegar al evento $t$, respondemos todas las consultas cuyo punto medio era $t$. Actualizamos sus límites y repetimos hasta que todas converjan.

## Ejemplo sencillo para entender las rondas

Cada evento añade un valor no negativo a un total. Queremos saber cuándo se alcanza cada meta positiva. Para aportaciones `[2, 1, 4]`, los totales son `[2, 3, 7]`. Las metas 1, 3 y 8 se alcanzan en los eventos 1, 2 y nunca.

En este ejemplo particular bastaría un arreglo de prefijos y búsquedas normales. Lo usamos para aislar el mecanismo; la ventaja real aparece cuando actualizar una estructura compartida es mucho más barato que reconstruirla por consulta.

## C++17

`n + 1` representa «nunca». Las metas son positivas; una meta ya satisfecha antes del primer evento necesitaría tratar el tiempo cero aparte.

```cpp test
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int eventos, consultas;
    cin >> eventos >> consultas;
    vector<long long> aporte(eventos + 1), meta(consultas);
    for (int tiempo = 1; tiempo <= eventos; tiempo++) cin >> aporte[tiempo];
    for (long long& valor : meta) cin >> valor;
    vector<int> izquierda(consultas, 1), derecha(consultas, eventos + 1);
    while (true) {
        vector<vector<int>> cubeta(eventos + 1);
        bool pendientes = false;
        for (int consulta = 0; consulta < consultas; consulta++) {
            if (izquierda[consulta] == derecha[consulta]) continue;
            pendientes = true;
            int medio = izquierda[consulta] + (derecha[consulta] - izquierda[consulta]) / 2;
            cubeta[medio].push_back(consulta);
        }
        if (!pendientes) break;
        long long total = 0;
        for (int tiempo = 1; tiempo <= eventos; tiempo++) {
            total += aporte[tiempo];
            for (int consulta : cubeta[tiempo]) {
                if (total >= meta[consulta]) derecha[consulta] = tiempo;
                else izquierda[consulta] = tiempo + 1;
            }
        }
    }
    for (int respuesta : izquierda) cout << (respuesta <= eventos ? respuesta : -1) << '\n';
}
```

Entrada:

```text input
3 3
2 1 4
1 3 8
```

Salida:

```text output
1
2
-1
```

## Por qué funciona y cuánto cuesta

Cada búsqueda conserva el intervalo de posibles primeras respuestas, incluyendo el centinela. Evaluar una cubeta da exactamente el estado tras su punto medio, porque el barrido procesa los eventos en orden. Así, cada ronda equivale a un paso de cada búsqueda independiente.

Con actualizaciones y evaluaciones constantes, cuesta $O((n+q)\log(n+1))$ tiempo y $O(n+q)$ espacio. Para otra estructura debes multiplicar por el coste real de actualizar y consultar.

No olvides reiniciar el estado al comienzo de cada ronda. Si hay eventos negativos que pueden deshacer la condición, esta búsqueda deja de estar justificada.

## Practica

¿Qué respuestas obtienes para aportaciones `[0, 0, 5]` y metas 1, 5 y 6?

<details>
<summary>Respuesta</summary>

3, 3 y -1. Los ceros conservan la monotonía; no hace falta que el total crezca estrictamente. Prueba también cero eventos: con metas positivas, todas las respuestas son -1.
