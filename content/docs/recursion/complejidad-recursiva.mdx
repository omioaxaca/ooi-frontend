## Podar exige demostrar que no pierdes respuestas

Una **poda** evita explorar una rama cuando sabemos que ninguna de sus continuaciones puede servir. No basta con que parezca poco prometedora.

Contemos subconjuntos cuya suma sea un objetivo no negativo. Si todos los valores son no negativos y la suma parcial ya excedió el objetivo, añadir otros elementos no puede reducirla. Por eso podemos regresar inmediatamente. Con `[5, -4]` y objetivo 1, esa misma regla sería incorrecta: el 5 todavía podría completarse con -4.

```cpp test
#include <iostream>
#include <vector>
using namespace std;

long long contar(const vector<int>& valores, int posicion, long long suma, long long objetivo) {
    if (suma > objetivo) return 0;
    if (posicion == static_cast<int>(valores.size())) return suma == objetivo ? 1 : 0;
    return contar(valores, posicion + 1, suma, objetivo)
         + contar(valores, posicion + 1, suma + valores[posicion], objetivo);
}

int main() {
    vector<int> valores = {2, 4, 7};
    cout << contar(valores, 0, 0, 6) << '\n';
}
```

Salida:

```text output
1
```

La única solución es elegir 2 y 4. El programa cuenta subconjuntos de **posiciones**, de modo que copias iguales siguen siendo opciones diferentes. El conteo debe caber en `long long`.

Una suma que ya coincide con el objetivo no autoriza a detenerse: podrían quedar ceros que generan otros subconjuntos válidos. Por eso aceptamos solamente al llegar al final.

## El peor caso puede seguir siendo exponencial

Si todos los valores son cero y el objetivo es cero, ninguna rama se poda. Hay $2^n$ hojas y $2^{n+1}-1$ llamadas en el árbol completo: tiempo $O(2^n)$ y espacio adicional $O(n)$ por la pila. Tiempo y profundidad no son lo mismo.

Otra poda posible compara la suma actual más **todo lo que aún queda** con el objetivo: si ni siquiera así lo alcanzas, puedes descartar la rama. También necesita supuestos sobre los valores y una cota que no subestime las continuaciones.

**Practica:** para `[0, 0]` y objetivo 0, la respuesta es 4. Explica por qué devolver 1 en cuanto `suma == objetivo` daría una respuesta incorrecta. Después prueba `[1, 2, 3]` con objetivo 3: hay dos soluciones.

## ¿Por qué analizar la recursión?

Cuando escribes una función recursiva, necesitas saber: ¿cuánto tiempo tarda? ¿cuánta memoria usa? Esto es especialmente importante en competencias, donde hay límites estrictos de tiempo y memoria.

## Método 1: Árbol de recursión

Dibuja todas las llamadas como un árbol y cuenta:

### Factorial: $O(n)$

```
factorial(5)
└── factorial(4)
    └── factorial(3)
        └── factorial(2)
            └── factorial(1)
                └── factorial(0)  ← caso base
```

Es una cadena lineal de $n+1$ llamadas. Cada llamada hace $O(1)$ trabajo. **Total: $O(n)$.**

### Fibonacci (sin memo): $O(2^n)$

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) ──...
│   │   └── fib(1)
│   └── fib(2) ──...
└── fib(3)
    ├── fib(2) ──...
    └── fib(1)
```

Es un árbol de llamadas de profundidad $O(n)$ cuyo número de nodos está acotado por $O(2^n)$. Esta es una cota superior; no afirma que el árbol esté completo.

### Fibonacci (con memo): $O(n)$

Cada valor de 0 a n se calcula exactamente una vez. **Total: $O(n)$.**

## Método 2: Relación de recurrencia

Expresa el tiempo como una fórmula recursiva y resuélvela:

### Ejemplo: Búsqueda binaria

```cpp
int busqueda(vector<int> &v, int lo, int hi, int x) {
    if (lo > hi) return -1;
    int mid = (lo + hi) / 2;
    if (v[mid] == x) return mid;
    if (v[mid] < x) return busqueda(v, mid+1, hi, x);
    return busqueda(v, lo, mid-1, x);
}
```

Recurrencia: $T(n) = T(n/2) + O(1)$

En cada llamada, el problema se reduce a la mitad. Después de $k$ pasos, $n / 2^k = 1$, así que $k = \log_2 n$.

**Total: $O(\log n)$.**

### Ejemplo: Merge Sort

```cpp
void mergeSort(vector<int> &v, int lo, int hi) {
    if (lo >= hi) return;
    int mid = (lo + hi) / 2;
    mergeSort(v, lo, mid);      // Primera mitad
    mergeSort(v, mid+1, hi);    // Segunda mitad
    merge(v, lo, mid, hi);      // Combinar: O(n)
}
```

Recurrencia: $T(n) = 2T(n/2) + O(n)$

Dos subproblemas de tamaño $n/2$, más $O(n)$ para combinar. **Total: $O(n \log n)$.**

## Recurrencias comunes

| Recurrencia             | Complejidad   | Ejemplo                              |
| ----------------------- | ------------- | ------------------------------------ |
| $T(n) = T(n-1) + O(1)$  | $O(n)$        | Factorial, búsqueda lineal recursiva |
| $T(n) = T(n-1) + O(n)$  | $O(n^2)$      | Selection sort recursivo             |
| $T(n) = 2T(n-1) + O(1)$ | $O(2^n)$      | Fibonacci, torres de Hanoi           |
| $T(n) = T(n/2) + O(1)$  | $O(\log n)$   | Búsqueda binaria                     |
| $T(n) = 2T(n/2) + O(n)$ | $O(n \log n)$ | Merge sort                           |
| $T(n) = 2T(n/2) + O(1)$ | $O(n)$        | Recorrer árbol binario               |

## Complejidad espacial

La recursión usa espacio en la **pila de llamadas**. La profundidad máxima de la pila = la profundidad del árbol de recursión.

| Función              | Profundidad de recursión | Espacio                          |
| -------------------- | ------------------------ | -------------------------------- |
| Factorial            | $n$                      | $O(n)$                           |
| Fibonacci (sin memo) | $n$                      | $O(n)$                           |
| Búsqueda binaria     | $\log n$                 | $O(\log n)$                      |
| Merge sort           | $\log n$                 | $O(n)$ (por el arreglo auxiliar) |

## Consejos prácticos

1. **Si la recursión es lineal** (una sola llamada recursiva por nivel), la complejidad suele ser simple de analizar.

2. **Dos llamadas no implican por sí solas tiempo exponencial**. Importa cuánto disminuye cada subproblema: merge sort divide el tamaño a la mitad y cuesta $O(n\log n)$; Fibonacci sin memoria repite muchos estados casi del mismo tamaño.

3. **Con memorización**, la complejidad es: (número de estados) × (trabajo por estado).

4. **En competencias**, tamaños cercanos a 20 sugieren que explorar subconjuntos podría ser viable, pero cuenta el trabajo por candidato, la salida y el límite de tiempo. No es una garantía universal.

## Ejercicio de práctica

Analiza la complejidad de esta función. ¿Cuántas veces se imprime "hola"?

```cpp
void misterio(int n) {
    if (n <= 0) return;
    cout << "hola" << endl;
    misterio(n / 3);
    misterio(n / 3);
}
```

<details>
<summary>Ver solución</summary>

$T(n) = 2T(n/3) + O(1)$

Usando el teorema maestro con $a=2$, $b=3$, $c=0$: como $\log_3 2 \approx 0.63 > 0$, la complejidad es $O(n^{\log_3 2}) \approx O(n^{0.63})$.

En términos simples: crece más rápido que $O(\log n)$ pero mucho más lento que $O(n)$.

</details>

## Conexión con memorización

La [memorización](/blog/recursion/memorizacion) evita recalcular estados equivalentes. La poda descarta ramas que no pueden servir. Son ideas distintas y pueden combinarse cuando sus condiciones lo permiten.
