## El problema de la recursión ingenua

**Antes de empezar:** repasa estados recursivos. Una memoria es válida solo si su clave incluye toda la información que determina la respuesta. Si cambian las monedas permitidas, obstáculos u otros datos del problema, quizá debas reiniciar la tabla.

## Una versión completa con límites explícitos

Usamos -1 como «pendiente» porque los resultados de Fibonacci son no negativos. La tabla se crea una vez y se pasa por referencia; crear una tabla nueva en cada llamada no compartiría los resultados.

```cpp test
#include <iostream>
#include <vector>
using namespace std;

long long fibonacci(int indice, vector<long long>& memoria) {
    if (indice <= 1) return indice;
    if (memoria[indice] != -1) return memoria[indice];
    memoria[indice] = fibonacci(indice - 1, memoria) + fibonacci(indice - 2, memoria);
    return memoria[indice];
}

int main() {
    int indice;
    cin >> indice;
    if (indice < 0 || indice > 92) return 0;
    vector<long long> memoria(indice + 1, -1);
    cout << fibonacci(indice, memoria) << '\n';
}
```

Entrada:

```text input
10
```

Salida:

```text output
55
```

Fibonacci exacto hasta índice 92 cabe en `long long`; índices mayores no. La tabla y la pila usan $O(n)$ espacio y el trabajo es $O(n)$. Para profundidades grandes, tabular de menor a mayor evita el límite de la pila. Las versiones de conteo con `int` mostradas como fragmentos más abajo solo sirven mientras sus respuestas quepan; usa módulo cuando el problema lo requiera.

**Autocomprobación:** si un resultado válido pudiera ser -1, necesitarías una marca separada como `calculado`, no ese mismo centinela. Guardar una respuesta antes de que sus dependencias terminen tampoco resuelve ciclos entre estados.

Recordemos la función de Fibonacci recursiva:

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```

Para calcular `fib(5)`, la función hace estas llamadas:

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2)
│   │   │   ├── fib(1) = 1
│   │   │   └── fib(0) = 0
│   │   └── fib(1) = 1
│   └── fib(2)          ← ¡Ya lo calculamos!
│       ├── fib(1) = 1
│       └── fib(0) = 0
└── fib(3)               ← ¡Ya lo calculamos!
    ├── fib(2)           ← ¡Ya lo calculamos!
    │   ├── fib(1) = 1
    │   └── fib(0) = 0
    └── fib(1) = 1
```

¡`fib(2)` se calcula **3 veces** y `fib(3)` se calcula **2 veces**! Para `fib(50)`, hay miles de millones de llamadas repetidas. El tiempo es $O(2^n)$: ¡imposible!

**Analogía:** Es como si cada vez que necesitas saber cuánto es $7 \times 8$, hicieras toda la multiplicación desde cero, en lugar de simplemente recordar que es 56.

## La solución: memorizar

La idea es simple: **antes de calcular algo, verifica si ya lo calculaste. Si sí, usa el resultado guardado. Si no, calcúlalo y guárdalo para el futuro.**

```cpp
long long memo[101];  // Arreglo para guardar resultados
bool calculado[101];  // Para saber si ya se calculó

long long fib(int n) {
    if (n <= 1) return n;
    if (calculado[n]) return memo[n];  // Si ya lo calculamos, retornarlo

    memo[n] = fib(n-1) + fib(n-2);    // Calcular
    calculado[n] = true;               // Marcar como calculado
    return memo[n];
}
```

### Versión más limpia con -1 como "no calculado"

```cpp
long long memo[101];

void init() {
    memset(memo, -1, sizeof(memo));  // Llenar todo con -1
}

long long fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];  // Ya calculado

    return memo[n] = fib(n-1) + fib(n-2);  // Calcular y guardar
}
```

### ¿Qué cambió?

Ahora el árbol de llamadas se "poda":

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2)
│   │   │   ├── fib(1) = 1
│   │   │   └── fib(0) = 0
│   │   └── fib(1) = 1
│   └── fib(2) = 1  ← ¡Ya guardado! O(1)
└── fib(3) = 2      ← ¡Ya guardado! O(1)
```

De $O(2^n)$ pasamos a $O(n)$: cada estado no base se desarrolla una vez y las consultas posteriores reutilizan su resultado.

## Cuándo usar memorización

La memorización funciona cuando se cumplen dos condiciones:

1. **Estados repetidos:** la misma pregunta aparece varias veces y reutilizar su respuesta evita trabajo.
2. **Respuesta estable para una clave completa:** el mismo estado con los mismos datos debe devolver lo mismo. No es necesario que sea un problema de optimización; también puedes memorizar conteos o decisiones.

Esto es la base de la **Programación Dinámica** (que veremos más adelante).

## Ejemplo: subir escaleras

**Problema:** Puedes subir una escalera de 1 o 2 escalones a la vez. ¿De cuántas formas puedes subir N escalones?

```
n=1: 1 forma (1)
n=2: 2 formas (1+1, 2)
n=3: 3 formas (1+1+1, 1+2, 2+1)
n=4: 5 formas
```

**Sin memorización** (lento):

```cpp
int formas(int n) {
    if (n <= 1) return 1;
    return formas(n-1) + formas(n-2);
}
```

**Con memorización** (rápido):

```cpp
int memo[100001];

int formas(int n) {
    if (n <= 1) return 1;
    if (memo[n] != -1) return memo[n];
    return memo[n] = formas(n-1) + formas(n-2);
}
```

## Ejemplo: caminos en una cuadrícula

**Problema:** En una cuadrícula de $m \times n$, ¿cuántos caminos hay desde la esquina superior izquierda hasta la inferior derecha, si solo puedes moverte hacia abajo o hacia la derecha?

```cpp
int memo[101][101];

int caminos(int m, int n) {
    if (m == 1 || n == 1) return 1;
    if (memo[m][n] != -1) return memo[m][n];
    return memo[m][n] = caminos(m-1, n) + caminos(m, n-1);
}

int main() {
    memset(memo, -1, sizeof(memo));
    cout << caminos(3, 3) << endl;  // 6
    return 0;
}
```

## De recursión con memo a iteración (bottom-up)

La memorización es **top-down** (empiezas del problema grande y descompones). Puedes convertirla a **bottom-up** (empiezas de los problemas pequeños y construyes):

```cpp
// Fibonacci top-down (recursivo con memo)
long long fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fib(n-1) + fib(n-2);
}

// Fibonacci bottom-up (iterativo)
long long fibIterativo(int n) {
    vector<long long> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    return dp[n];
}
```

Ambos son $O(n)$, pero el iterativo evita el overhead de la recursión y el riesgo de stack overflow.

## Ejercicio de práctica

Usa memorización para calcular el coeficiente binomial $C(n, k) = \binom{n}{k}$ usando la relación: $C(n, k) = C(n-1, k-1) + C(n-1, k)$, con $C(n, 0) = C(n, n) = 1$.

<summary>Ver solución</summary>

```cpp
#include <iostream>
#include <cstring>
using namespace std;

long long memo[101][101];

long long C(int n, int k) {
    if (k == 0 || k == n) return 1;
    if (memo[n][k] != -1) return memo[n][k];
    return memo[n][k] = C(n-1, k-1) + C(n-1, k);
}

int main() {
    memset(memo, -1, sizeof(memo));

    int n, k;
    cin >> n >> k;
    cout << C(n, k) << endl;

    return 0;
}
```
